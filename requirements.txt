# KiCad Routing Tools Dependencies
#
# KiCad 10 provisions a per-plugin venv from this file on first action
# invocation, so anything listed here gets pip-installed automatically.

# KiCad IPC client (replaces the in-process SWIG `pcbnew` module)
kicad-python>=0.7.0

# wxPython is no longer bundled with KiCad once the plugin is out-of-process,
# so install it explicitly into the venv.
wxPython~=4.2

# Numerical computation.
#
# The numpy floor is 1.22, not 1.21, and it is load-bearing rather than
# aspirational -- the whole stack breaks below it in ways that name neither
# numpy nor us (reported from a KiCad 10 install, 2026-09-18):
#   * `numpy._DTypeMeta.__class_getitem__` landed in 1.22. Below that, any
#     package whose import evaluates `np.ndarray[Any, np.dtype[...]]` dies with
#     `TypeError: 'numpy._DTypeMeta' object is not subscriptable`.
#   * scipy >= 1.11 warns "A NumPy version >=1.22.4 and <2.3.0 is required for
#     this version of SciPy (detected version X)".
# `startup_checks.requirement_floors` READS this line, so the floor here is the
# floor the gates enforce -- see FALLBACK_FLOORS there for the stripped-install
# case. Raising it here raises it everywhere; there is no second copy to edit.
numpy>=1.22.0
scipy>=1.7.0

# Geometry operations. 2.0 for the vectorized API: the courtyard reader
# (placement/parser.py, #1094) calls shapely.distance / shapely.points.
shapely>=2.0

# macOS-only: lets the spawned plugin process become the frontmost app so
# the wx dialog opens in front of KiCad instead of behind it.
pyobjc-framework-Cocoa; sys_platform == 'darwin'

# Rasterization: board stills and review sheets.
# Listed because a fresh clone that followed the README could not render
# anything without it -- but it is the RASTER path and nothing else, so its
# absence DISABLES rendering rather than stopping anything (#943).
#
# ONE file imports it at module scope: py_router/route_render.py, which is the
# raster stack and nothing else, and which calls
# `startup_checks.check_render_dependencies` first so the message is the
# actionable one. py_tools/render_placement.py used to be the second, and its
# import moved into the five functions that DRAW because that module also holds
# PlacementModel / legality_findings, which py_tools/board_context.py and the
# stress predictors import to GRADE a placement and draw nothing.
#
# Routing does not touch it, and neither does the GUI plugin. On this branch
# there is no `deps_check` (main's OPTIONAL_PACKAGES lives in the SWIG entry
# point, deleted by the port) -- KiCad provisions the venv from this file, so
# Pillow is simply present; if a hand-made venv lacks it, the placement
# preview turns itself off rather than raising a dialog nobody can dismiss
# (#943).
#
# The floor is deliberately LOW: everything the renderer needs (alpha_composite,
# LANCZOS, ImageChops, PngInfo) is far older than this, and a low floor keeps
# older environments working. Captions want more: route_render.load_font asks
# for a SIZED default font, ImageFont.load_default(size=), which arrived in
# Pillow 10.1.0 -- below that its try/except falls back to the unsized default
# and labels come out small but present. So 10.1 is the version to have, not the
# version to require.
#
# (A previous comment here put load_default(size=) at 9.2. That is wrong -- it
# is 10.1.0 -- and the error is worth naming because it was pinned INTO a
# dependency declaration, where "the version at which the intended path works"
# would then have been false.)
Pillow>=9.2.0

# The bus step: awx/route_bus.py and the whole route behind it plan with
# Google OR-Tools' CP-SAT -- its fanout's joint escape, the ends model and the
# whole solve import `ortools.sat.python.cp_model` (#1355). Without it the step
# used to run for minutes and lay nothing, the ModuleNotFoundError left in a
# stage log. ROUTING does not need it -- route.py and the other routing CLIs
# never import it -- and neither does the GUI plugin, so, like Pillow, it is in
# `deps_check.OPTIONAL_PACKAGES` and has a gate of its own,
# `startup_checks.check_bus_dependencies`, which route_bus.py and
# whole_route.py call before they start. 9.15 is the version the bus step is
# run and measured on (awx/modal_whole.py pins 9.15.6755): it sets recent
# CP-SAT parameters (max_num_deterministic_batches, share_glue_clauses), and
# CP-SAT's plans move between versions.
#
# NOT LISTED ON ipc-migration: it cannot share an environment with
# kicad-python. ortools 9.15 requires protobuf>=6.33.1 and every kicad-python
# release (0.7.x, 0.8.0) protobuf<6, so pip refuses the whole file
# (ResolutionImpossible) -- and KiCad provisions the plugin's venv from this
# file, so listing it broke the plugin's install, not just the bus step. The
# bus step is a CLI step the plugin never runs; install it into a separate
# environment (`pip install "ortools>=9.15"`), which its gate names when it is
# missing. tests/test_887_small_items.py counts it as declared through
# BUS_PACKAGES on this branch.
